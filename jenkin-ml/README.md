# Deploy Machine Learning Model Using Jenkins Pipeline

## 1. Introduction

This project demonstrates the automation of a Machine Learning workflow using Jenkins, Python, Scikit-learn, and Flask.

Jenkins is a Continuous Integration and Continuous Delivery (CI/CD) automation server. It automates repetitive development tasks by executing a sequence of stages defined in a pipeline.

In this project, Jenkins retrieves the source code from GitHub, installs the required Python libraries, trains a Machine Learning model, tests its accuracy, and deploys the trained model using a Flask web application.

The project uses the Iris dataset to classify flowers into three species: setosa, versicolor, and virginica.

## 2. Aim

To create a Jenkins pipeline that automatically trains, tests, and deploys a Machine Learning model.

The project follows this workflow:

```text
       Developer's ML Project
                 |
                 v

                 |
                 v
          Jenkins Pipeline
                 |
                 v
        Clone Source Code
                 |
                 v
       Install Dependencies
                 |
                 v

                 |
                 v
            Test Model
                 |
                 v
          Deploy with Flask
                 |

                 |
```

Each stage runs after the previous stage succeeds. If a stage fails, Jenkins stops the pipeline rather than continuing to subsequent stages.

## 5. Project Structure

```text
jenkin-ml/
├── Jenkinsfile
├── train.py
├── test.py
├── app.py
├── requirements.txt
└── model.joblib
```

**Jenkinsfile:** Defines the automated pipeline stages.

**train.py:** Loads the Iris dataset, trains a Random Forest classifier, and saves the trained model.

**test.py:** Loads the trained model, evaluates its predictions on test data, calculates accuracy, and fails the test if accuracy is below 80%.

**app.py:** Loads the saved model and provides a Flask web application with a prediction API.

**requirements.txt:** Lists the Python libraries required to run the project.

**model.joblib:** Contains the serialized trained model. This file is generated by `train.py` and should be produced during the Jenkins training stage.

## 6. How the Project Works

### Step 1: Source Code Management

The project is stored in a GitHub repository:

https://github.com/Shubhamkumar-op/DOML-LAB

Jenkins uses Git to retrieve the latest code from the `main` branch. The pipeline loads its instructions from `jenkin-ml/Jenkinsfile`.

### Step 2: Install Dependencies

Jenkins creates a Python virtual environment inside the workspace and installs the libraries listed in `requirements.txt`.

The required packages are:

- `scikit-learn`: Used to load the Iris dataset, train the classifier, and evaluate predictions.
- `joblib`: Used to save and load the trained Machine Learning model.
- `flask`: Used to expose the model through HTTP endpoints.

### Step 3: Train the Machine Learning Model

The `train.py` script performs the following operations:

1. Loads the Iris dataset using Scikit-learn.
2. Splits the dataset into training and testing portions, with 80% allocated to training and 20% to testing.
3. Creates a Random Forest Classifier.
4. Trains the model using the training data.
5. Saves the trained model as `model.joblib`.

The `random_state=42` parameter is used to make the data split and model training reproducible under the same software environment.

The training stage prints:

```text
Model trained successfully!
Model saved as model.joblib
```

### Step 4: Test the Trained Model

The `test.py` script checks whether the trained model works correctly.

It loads the Iris dataset and recreates the same train-test split. It then loads `model.joblib`, predicts the labels for the test data, and calculates accuracy using Scikit-learn.

The test fails if the accuracy is below `0.80` (80%). If the accuracy meets the threshold, the script prints:

```text
Model Accuracy: 1.0
Testing completed successfully!
Model test passed!
```

An accuracy of `1.0` means that all predictions in this particular test split were correct. It does not guarantee that the model will achieve 100% accuracy on every future dataset.

### Step 5: Deploy the Model

The `app.py` script loads the trained model from `model.joblib` and starts a Flask web application.

The application provides two endpoints:

**Home endpoint — `/`**

Opening `http://localhost:5000` returns:

```text
ML Model is deployed successfully!
```

Jenkins uses this endpoint as a health check to verify that the Flask server responds successfully.

**Prediction endpoint — `/predict`**

This endpoint accepts an HTTP POST request containing four Iris flower measurements in JSON format.

Example request:

```json
{
  "features": [5.1, 3.5, 1.4, 0.2]
}
```

The model predicts the flower species and returns a JSON response, for example:

```json
{
  "prediction": "setosa"
}
```

The prediction depends on the supplied feature values.

## 7. Jenkins Pipeline Explained

The `Jenkinsfile` defines five stages.

### Stage 1: Clone

Jenkins checks out the source code from the configured GitHub repository using the Jenkins SCM configuration.

### Stage 2: Install

Jenkins creates the Python virtual environment and installs the dependencies from `requirements.txt`.

### Stage 3: Train

Jenkins executes `train.py`, which trains the Random Forest classifier and generates `model.joblib`.

### Stage 4: Test

Jenkins executes `test.py`. It calculates the model's accuracy and checks whether it meets the required threshold of 80%.

If the test fails, Jenkins marks the build as failed and skips the later deployment stage.

### Stage 5: Deploy

Jenkins starts `app.py` as a background process, redirects its output to `app.log`, and checks whether the application responds successfully at `http://127.0.0.1:5000/`.

If the health check succeeds, the deployment stage prints:

```text
ML Model deployed successfully at http://localhost:5000
```

The pipeline is complete when all five stages finish successfully.

## 8. How to Run the Project

### Prerequisites

Ensure Java, Git, and Python are installed, and that Jenkins is running.

### Step 1: Open the project

```powershell
cd D:\DOML-LAB\jenkin-ml
```

### Step 2: Install dependencies locally (optional)

```powershell
py -3.13 -m pip install -r requirements.txt
```

### Step 3: Train the model locally

```powershell
py -3.13 train.py
```

### Step 4: Test the model locally

```powershell
py -3.13 test.py
```

### Step 5: Start Jenkins

Open:

http://localhost:8080

Sign in to Jenkins and open the `ML-Pipeline` job.

### Step 6: Run the pipeline

Click **Build Now** and open **Stage View** or **Console Output** to observe the execution of the stages.

### Step 7: Verify deployment

Open the deployed application:

http://localhost:5000

The home page should display:

`ML Model is deployed successfully!`

The prediction endpoint is available at:

`http://localhost:5000/predict`

It accepts POST requests rather than a normal browser GET request.

- The Random Forest model was trained.
- The model test passed with the observed accuracy.

## 10. Benefits of the Project

- Reduces repetitive manual execution.

- Provides a simple HTTP interface for predictions.
- Makes the execution process visible through Jenkins logs and stage status.

## 11. Limitations

- The application runs locally on the Jenkins machine; it is not deployed to a cloud server.
- The Flask development server is suitable for this lab demonstration, not production deployment.
- The model accuracy is measured on a single test split and should not be treated as a guarantee of future performance.
- The Jenkinsfile uses a Windows-specific Python installation path, which must be adjusted on a different machine.
- The prediction API expects exactly four feature values.

## 12. Conclusion

The project successfully demonstrates an automated Machine Learning pipeline using Jenkins. The pipeline retrieves source code from GitHub, installs dependencies, trains a Random Forest model, tests its accuracy, and starts a Flask application for serving predictions. This experiment illustrates how CI/CD automation can be applied to a basic Machine Learning workflow.
